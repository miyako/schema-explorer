# schema-explorer

[Open Schema orbit](https://miyako.github.io/schema-explorer/), an interactive,
read-only WebGPU explorer of a **synthetic** 4D commerce schema: 12 tables and
14 resolved relations, including a self-relation. You can also open your own
local XML catalog without uploading it.

## Explore

Drag empty space to orbit, Shift-drag or right-drag to pan, and wheel/pinch to
zoom. Select a table to inspect all fields and relations. Drag a card to move
it, double-click to collapse/restore, or use the inspector to focus, isolate
neighbors, and push/pull depth. Each sidebar entry also has a `-`/`+` table
toggle; **Collapse all** and **Restore all** work across the whole schema, even
when search or neighbor isolation is active. **Tables** and **Inspector** in
the header independently hide/restore the side panels.

Search matches table and field names. Selecting a result, focusing, fitting,
and changing to front view use a brisk 360 ms camera transition. Table
collapse/restore animates its height, content, and relation anchors over
260 ms. Reset layout smoothly restores the sample positions, expansion,
depth, and camera. Direct orbit/pan/zoom interrupts camera animation.
With the canvas focused, arrows pan, `+`/`-` zoom, `F` fits, and Escape clears
selection.

A current WebGPU-enabled browser and supported graphics device are required
(for example Chrome, Edge, or Safari 26 with hardware acceleration). HTTPS or
localhost is required. Unsupported browsers and adapter/device errors display
an explicit error; there is no WebGL/SVG fallback. The table list and inspector
remain available if GPU initialization fails.

## Relation-flow choices

[Compare animated line styles](https://miyako.github.io/schema-explorer/flow-comparison.html):
the original reference plus **A / Soft**, **B / Fine**, and **C / Subtle**.
Both normal and selected relations use the explorer's actual ribbon geometry
and shared WGSL flow fragment. All alternatives hold pulse length at 20%.
A uses 30% light / 30% gaps, B uses 20% / 20%, and C uses 10% / 10%,
while keeping the route, speed, base line, and colors the same.
Percentages are relative to the original setting. **B / Fine** is the explorer's
selected default: 20% light, 20% pulse length, and 20% gaps, with unchanged speed.
Reduced-motion preferences show static previews.

## Open a local catalog

Choose **Open local file**, select a `catalog.4DCatalog`, and optionally select
its matching `catalog_editor.json` in the second picker, then choose
**Open locally**. The browser cannot silently discover adjacent files.
The optional companion's valid coordinates override embedded XML coordinates
by unique table name; otherwise embedded positions or the automatic grid are
used. **Return to demo** clears the local scene and restores the synthetic
sample. Reloading also clears the local scene; the app does not save it.

Selected file contents, filenames, and derived schema data stay in browser
memory: no uploads, server parsing, analytics, URL embedding, or local/session
storage. The page's Content Security Policy blocks all fetch/XHR/WebSocket
connections and form submissions. Only the app's static modules and stylesheet
are loaded; even the synthetic sample is a bundled module, not a runtime fetch.
Names from catalogs are rendered as text, never HTML.

The browser decoder follows `4d-ql`'s `CatalogAnalyzer` for direct-child XML
elements, field flags and types, primary keys, normalized UUID/name resolution,
unresolved-relation warnings, and layout precedence. A synthetic golden fixture
is compared with the Swift parser's output. UTF-8, UTF-16 LE/BE, and
browser-supported declared legacy XML encodings are supported. Binary
`.4DB`/`.4DD` databases and UTF-32 are not supported.

Limits are 32 MiB for XML, 4 MiB for UTF-8 layout JSON, 200,000 XML elements,
XML nesting below 128, and JSON depth 64 / 100,000 values. Custom entities and
internal DTD subsets are rejected; an ordinary external 4D DTD declaration is
inert and is not fetched. Malformed files, duplicate JSON keys, unsupported
encodings, and unsafe integer attributes produce explicit errors or parser
notes. An invalid layout JSON document rejects the import rather than silently
ignoring the selected file. Invalid per-table coordinates produce visible notes
and preserve embedded positions. A rejected import leaves the current scene
unchanged. Large catalogs can briefly pause the UI while parsing on the main
thread.

## Static hosting and privacy

Only `site/` is deployed by `.github/workflows/pages.yml` on pushes to `main`.
All asset imports are relative to the project URL. No Python, Swift,
4D runtime, build step, external CDN, catalog upload, or database connection is
used by the published site.

`site/sample.mjs` contains the synthetic example generated by
[`miyako/4d-ql`](https://github.com/miyako/4d-ql)'s `schema-webgpu/serve.py` and
parsed by its existing `fourdql --json` command (source commit `77896d8`).
The frontend is adapted from that implementation. The fixture contains no
private/local user catalog contents. Do not replace it with a private catalog:
everything deployed to Pages is public.

Cards have actual extruded glass-panel geometry, tinted translucent faces,
and highlighted rims (not physically accurate refraction). Curved relations
carry continuously animated pulses **from the many-side (N) field to the
one-side (1) field**, including self-relations. Flow is shader-driven with
cached geometry between interactions; hidden tabs stop rendering. The system
**reduced-motion** preference makes transitions immediate and disables moving
flow, preserving static relation arrows.

Panels, relations, arrows, and the grid are rendered using WebGPU/WGSL.
Canvas 2D only rasterizes text and decoration into textures. Cards show up to
eight prioritized fields; the inspector shows every field. At most 128 visible
cards receive detailed textures. This is a demo, not a database editor or a
million-node renderer. Layout changes are in-memory only, with no persistence.

## Local development

```sh
python3 -m http.server 4181 --bind 127.0.0.1 --directory site
```

Open `http://127.0.0.1:4181/`; do not open `index.html` directly.

```sh
node --test tests/*.test.mjs
```

For the dependency-free native-browser checks, serve the repository root
(`python3 -m http.server 4182 --bind 127.0.0.1`) and open
`http://127.0.0.1:4182/tests/browser.html`. Only synthetic test files are used.
The workflow runs this suite in headless Chrome as well as the Node checks
before deployment, including golden-parser parity, encodings, malformed files,
size/depth limits, and local-file UI requests/storage/URL checks.

Model tests cover picking,
layout, field priorities, self-relations, camera fitting, and interruptible
transitions. Renderer checks cover panel depth and directional flow geometry;
publication tests check the synthetic fixture and project-relative assets.
